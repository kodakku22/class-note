# Commercial Readiness Checklist

## Release Secrets

Configure these repository secrets before publishing a public build:

- `WINDOWS_CERTIFICATE_BASE64`: base64-encoded `.pfx` code-signing certificate.
- `WINDOWS_CERTIFICATE_PASSWORD`: password for the certificate.
- `SENTRY_DSN`: Sentry project DSN. Leave empty to disable crash reporting.
- `TELEMETRY_ENDPOINT`: optional anonymous telemetry endpoint.

## Quality Gates

Every pull request should pass:

```bash
npm run lint
npm test -- --run
npm run test:coverage
npm run build
npm audit
npm audit --omit=dev
npm run license:check
```

## Release Flow

1. Update `package.json` version.
2. Update `CHANGELOG.md`.
3. Commit the release.
4. Create a tag such as `v0.1.1`.
5. Push the tag.
6. Review the draft GitHub Release generated by `.github/workflows/release.yml`.
7. Download and smoke-test `ClassNotes-*-Setup.exe`.
8. Verify `SHA256SUMS.txt` with `npm run test:release-artifacts`.
9. Publish the draft release.

## Security Notes

- API keys are stored using Electron `safeStorage`, backed by OS encryption.
- The renderer never receives the decrypted API key.
- Crash reports require user opt-in and Sentry DSN configuration.
- Release builds exclude source maps, TypeScript sources, tests, and renderer-only package trees from ASAR.
- External file imports use one-use picker grants instead of renderer-visible raw paths.
- Diagnostics are local-only and redacted; see `docs/operations.md`.
- Threat model and reviewer checklist live in `docs/threat-model.md`.
